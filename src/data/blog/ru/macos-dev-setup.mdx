## Homebrew как фундамент

Первое, что я делаю после чистой установки macOS — ставлю Homebrew. Не браузер, не мессенджер. Именно brew.

За годы я пришёл к простому выводу: без единой точки управления софтом система быстро превращается в хаос. Часть приложений ставишь через .dmg, часть — из App Store, что-то через curl-скрипты из README. Через полгода уже не помнишь, откуда что взялось и как это обновлять.

Homebrew решает эту проблему: **один инструмент для установки, обновления и удаления**.

### Установка

Всё начинается с одной команды в терминале:

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

Скрипт сам установит Xcode Command Line Tools, если их ещё нет, и настроит brew под твою архитектуру (Intel или Apple Silicon).

После установки brew подскажет, что нужно добавить в `.zshrc` — обычно это путь к директории brew. На Apple Silicon это `/opt/homebrew`, на Intel — `/usr/local`.

Проверить, что всё работает:

```bash
brew doctor
```

Если видишь «Your system is ready to brew» — можно двигаться дальше.

Официальный сайт: [brew.sh](https://brew.sh)

### Структура: formulae, casks, taps

В Homebrew три ключевых понятия, и их полезно понимать с самого начала.

**Formulae** — это CLI-инструменты, библиотеки, рантаймы. Всё, что живёт в терминале: `git`, `node`, `ffmpeg`, `jq`. Устанавливаются командой `brew install`:

```bash
brew install git
brew install node
```

**Casks** — GUI-приложения. Браузеры, редакторы, мессенджеры. Всё, что обычно ставишь через .dmg:

```bash
brew install --cask visual-studio-code
brew install --cask firefox
```

Мне нравится это разделение: терминальное — formula, графическое — cask. При этом управляются они одинаково.

**Taps** — подключаемые репозитории с дополнительными формулами. По умолчанию brew работает с `homebrew/core` и `homebrew/cask`, но иногда нужно что-то, чего там нет. Например, шрифты:

```bash
brew tap homebrew/cask-fonts
brew install --cask font-jetbrains-mono
```

Или формулы от конкретного разработчика:

```bash
brew tap oven-sh/bun
brew install bun
```

### Как это работает под капотом

Homebrew не делает ничего магического. Когда выполняешь:

```bash
brew install --cask chatgpt
```

происходит примерно следующее:
- brew скачивает официальный .dmg с сайта OpenAI
- распаковывает его
- переносит .app в `/Applications`
- регистрирует пакет у себя

**Приложение остаётся официальным**, просто путь к нему становится контролируемым. Homebrew — это автоматизация ручных действий, а не альтернативный источник софта.

Формулы и casks проходят ревью сообщества. Каждый cask содержит checksum и ссылку на официальный источник. Если доверяешь сайту приложения — можешь доверять и cask'у.

### Обновления и обслуживание

Одно из главных преимуществ brew — простое обновление всего сразу.

Посмотреть, что устарело:

```bash
brew outdated
```

Обновить всё:

```bash
brew upgrade
```

Обновить конкретный пакет:

```bash
brew upgrade node
```

Периодически полезно запускать очистку — brew хранит старые версии пакетов:

```bash
brew cleanup
```

А `brew autoremove` удалит зависимости, которые больше не нужны.

Я запускаю `brew upgrade` примерно раз в неделю. Не автоматически — хочу видеть, что обновляется. Но и не забывать надолго.

### Где brew не подходит

Homebrew — не религия. Есть случаи, когда я ставлю софт иначе:
- приложение живёт только в App Store
- производитель навязывает собственный апдейтер, который конфликтует с brew
- нужен специфичный кастомный билд

Но это исключения. Для 90% софта brew — мой единственный путь установки.

### Почему это важно

`brew list` показывает всю картину: что установлено, откуда, какой версии. Не нужно гадать «а это приложение я откуда вообще ставил?»

А главное — я могу воспроизвести свой сетап на новой машине. Один `Brewfile`, одна команда, и базовый набор софта готов. Об этом подробнее в разделе про автоматизацию.
